# Build spec: "Cayley vs Schreier" — a single-file interactive explainer

Give this whole document to a coding LLM. It is written to be self-contained: an
assistant that has never seen the original app should be able to reproduce it
from this text alone. Sections marked **MUST** are acceptance criteria; the
assistant is expected to verify them before reporting done.

---

## 0. Role and goal

You are building a **single self-contained HTML file** (HTML + CSS + vanilla JS,
no build step, no network requests, no libraries) that teaches one specific
mathematical distinction:

> A **Cayley graph** has one vertex per *group element*. A **Schreier coset
> graph** has one vertex per *coset*. Graphs of the form
> G_c(k,n) = S_n / (S_k × S_{n−k}), generated by consecutive c-cycles acting on
> binary words, are Schreier graphs, not Cayley graphs — and they are routinely
> mislabeled as Cayley graphs in the literature.

The teaching device is an **animated collapse**: the Cayley graph is drawn on the
left, the Schreier graph on the right, and pressing START flies every Cayley
vertex onto its coset's position until the left panel becomes an exact copy of
the right one. The collapse *is* the difference between the two notions.

The file **MUST** open correctly from `file://` with a double-click, and must
also work unmodified when served from GitHub Pages.

## 2. The mathematics — get this exactly right

This is the part most likely to go wrong. Use these conventions verbatim.

### 2.1 Objects

- `n` = word length, `k` = number of zeros, `c` = cycle length of the generators
  (support c = 3 and c = 4).
- A permutation σ ∈ S_n is a 0-indexed array with `σ[i]` = the position that
  position `i` maps **to**.
- The canonical word is `A = 0^k 1^{n−k}`, i.e. `A[i] = (i < k ? 0 : 1)`.

### 2.2 Action on words

A permutation moves the symbol at position `i` to position `σ[i]`:

```
(σ · w)[ σ[i] ] = w[i]          for all i
```

### 2.3 Generators — consecutive c-cycles

For each window start `i` with `i + c ≤ n`, the forward generator `g` is:

```
g[i] = i + c − 1
g[j] = j − 1        for j = i+1 … i+c−1
g[j] = j            otherwise
```

Sanity check the assistant **MUST** run: applying `g` to a word must perform

```
x_i x_{i+1} … x_{i+c−1}   ↦   x_{i+1} … x_{i+c−1} x_i
```

Also include each inverse `g⁻¹` (so the graphs are undirected). Number of
generators = `2(n − c + 1)`.

### 2.4 The two graphs

**Schreier** `G_c(k,n)`:
- vertices = binary words of length n with exactly k zeros → `C(n,k)` of them
- edges = `{w, g·w}` for every generator g, discarding `w = g·w`

**Cayley** `Cay(S_n, generators)`:
- vertices = all `n!` permutations
- edges = `{σ, g∘σ}` where composition is **left multiplication**:
  `(g∘σ)[i] = g[σ[i]]`

### 2.5 The projection — why left multiplication

Define `π(σ) = σ · A`. Then

```
π(g∘σ) = (g∘σ)·A = g·(σ·A) = g·π(σ)
```

so π maps Cayley edges to Schreier edges (or to loops). **Right** multiplication
would break this — if the assistant uses `σ∘g` the panels will not correspond
and the collapse animation will be meaningless. This is the single most
important correctness detail in the build.

Consequences the app displays:

- `π(σ) = π(τ)` ⟺ σ and τ lie in the same **left coset** of
  `Stab(A) = S_k × S_{n−k}`
- every fiber has exactly `k!(n−k)!` elements
- `n! / (k!(n−k)!) = C(n,k)` — the vertex counts of the two panels

## 3. What the app must show

### 3.1 Page structure, top to bottom

1. **Header** — title "Cayley vs Schreier — why G_c(k,n) is not a Cayley graph",
   plus a 2–3 sentence lede ending in an instruction to press START.
2. **Control bar** (one card): `n` slider (3–6), `k` slider (1–n−1, clamped
   whenever n changes), a two-button segmented control for c ∈ {3,4}, and the
   three buttons **START / RESET / HELP** pushed to the right edge.
3. **Two panels side by side** (stack vertically below ~860px):
   - left, labeled **CAYLEY**: `Cay(S_n, consecutive c-cycles)`, subtitle
     "One vertex per **group element**. Every bead is a different color."
   - right, labeled **SCHREIER**: `G_c(k,n) = S_n/(S_k × S_{n−k})`, subtitle
     "One vertex per **coset**. Beads come in two colors only."
   - each panel: a canvas (~420px tall), a small overlay in the top-left showing
     the live room count, and a footer strip with `vertices · edges · components ·
     degree` (degree shown as `min–max`, or a single number when regular).
4. **Legend** line explaining the two vertex colors, the highlight color, and
   "hover either panel to light up one fiber".
5. **Four stat cards**: Cayley rooms (`n!`), Schreier rooms (`C(n,k)`), fiber size
   (`k!(n−k)!`), information lost (% of Cayley edges that become loops).
6. **A live prose paragraph** that rewrites itself on every (n,k,c) change — see §3.3.
7. **A findings table** listing where a source document names the object
   correctly or incorrectly (supply your own rows; see §6).
8. **HELP modal**, closed by default.

### 3.2 The bead rendering — this carries the analogy

Every vertex is drawn as a **row of n small circles ("beads")**, not a plain dot.

- Cayley panel: the bead at position `j` is the labeled bead `σ⁻¹[j]`, colored
  `hsl(360·label/n, 62%, 52%)` — all n labels distinguishable.
- Schreier panel: the bead at position `j` is dark (`rgb(35,42,58)`) if the word
  has a 0 there, light (`rgb(233,237,245)`) otherwise.
  **Do not use pure white** — it vanishes against the near-white canvas. Stroke
  every bead with a thin grey outline.
- During the collapse, each Cayley bead color interpolates from its rainbow hue
  to its two-color target, so the beads visibly "lose their labels".
- Above ~200 vertices (i.e. n = 6, 720 permutations), fall back to a single dot
  per vertex colored by its fiber, or the panel becomes unreadable.

### 3.3 The live paragraph

Regenerate on every parameter change. It must state, using the computed numbers:

- `n!` elements collapse onto `C(n,k)` cosets, each fiber holding `k!(n−k)!`.
- How many Cayley edges have both ends in one fiber (→ loops after collapse), or
  that there are none. Call this the information the collapse destroys.
- **If the Cayley graph is disconnected**, explain why: for odd c a c-cycle is an
  *even* permutation, so the generators reach only `A_n`, and a Cayley graph is
  connected only when its generators generate the whole group. Then add whether
  the Schreier graph is nevertheless connected (it usually is, because each coset
  mixes even and odd elements). **Do not skip this** — the user will otherwise
  read "components 2" as a bug.
- **If the Schreier graph is disconnected or non-regular**, say so, and point out
  that a Cayley graph is always vertex-transitive and therefore regular — so a
  non-regular graph cannot be one. This is the cleanest single argument against
  the "Cayley" name and the app should make it for the user.

Each of these is conditional. A sentence that is false for the current
parameters **MUST NOT** appear (e.g. do not say "the Schreier graph stays
connected anyway" when it has 2 components).

## 4. Algorithms

### 4.1 Layout — Fruchterman–Reingold with grid-binned repulsion

- Seed positions on a circle with jitter from a seeded xorshift PRNG.
- Ideal edge length `L = sqrt(W·H/N) · 0.78`.
- Repulsion `L²/d`, restricted to a 3×3 neighborhood of a grid with cell size
  `2L` — plain O(N²) repulsion is too slow at 720 vertices.
- Attraction `d²/L` along each edge.
- Cap each step's displacement at a temperature `t`, cooling by ×0.982 per step.
- Clamp to the canvas with ~26px padding.
- Run the simulation inside the animation loop until the temperature cools, so
  the layout visibly settles instead of blocking the page.
- Pre-settle the small Schreier graph (~260 steps) before first paint.

### 4.2 The collapse animation

- On START: snapshot the current Cayley positions (`from`), set `phase =
  "collapsing"`, record the start timestamp. Duration ≈ 2.6s.
- Target for Cayley vertex σ = the position of Schreier vertex `π(σ)`, rescaled
  by the ratio of the two canvases' dimensions.
- Interpolate with smoothstep `e = t²(3−2t)`, not linear.
- Fade every edge whose endpoints share a fiber by `(1−t)²` — those are exactly
  the edges that become loops, and watching them disappear is the point.
- When `t` reaches 1, change the left overlay to say the panel is now exactly
  the Schreier graph on the right.
- The room counter in the left overlay counts down `n!` → `C(n,k)` along the way.
- RESET rebuilds everything and re-runs the layout from the seed.

### 4.3 Hover

Hovering either canvas finds the nearest vertex within ~26px and sets a
`hoverFiber`. Then: in the Cayley panel every vertex of that fiber is outlined in
amber; in the Schreier panel the single corresponding vertex is outlined;
everything else dims to ~20% alpha and incident edges brighten. At n=5, k=2 this
lights exactly 12 Cayley vertices for 1 Schreier vertex — the `k!(n−k)!` factor,
seen rather than asserted.

Performance note: precompute bead colors into a cache of RGB triples and
interpolate numerically. Do **not** implement color mixing by writing to a
canvas context and reading back `fillStyle` — that is a per-bead per-frame
round-trip and it will drop the frame rate through the floor.

## 5. Visual design

Light, quiet, academic. Suggested tokens:

```
--bg:#f6f7fb  --card:#fff  --ink:#1c2230  --muted:#5b6478  --line:#dfe3ec
--cayley:#4f46e5   --cayley-soft:#eceafe
--schreier:#0d7f73 --schreier-soft:#e2f3f0
--highlight:#d97706
```

Cards with 1px borders, 12px radius, a barely-there shadow. Edges drawn at
alpha ≈0.20 (Cayley) / ≈0.34 (Schreier) so structure reads without noise.
Tabular numerals for every count. Uppercase 11px letter-spaced labels for stat
captions. No emoji, no gradients, no decorative icons.

## 6. Content to embed (replace with your own)

The original app included a table mapping line numbers in a specific LaTeX
manuscript to correct/incorrect usage, e.g.

| Line | Text | Verdict |
|---|---|---|
| 115 | "The **Cayley** graph G₃(k,n) generated from S_n/S_k×S_{n−k}" | wrong name |
| 3219 | "Let G₄(k,n) be the **Schreier** graph associated with S_n/(S_k × S_{n−k})" | correct |

It also flagged a notation slip worth keeping as a template: writing
`S_n/S_k×S_{n−k}` parses as `(S_n/S_k)×S_{n−k}`, a different object — the
parentheses in `S_n/(S_k×S_{n−k})` are load-bearing.

The HELP modal should contain, in plain language:
- **the bead analogy** — the Cayley graph is a map with one room per arrangement
  of n *labeled* beads; repaint them in two colors and you can no longer tell the
  k black ones apart, so blocks of rooms become one room. Same moves, coarser map.
- why the names differ, and that they coincide only for a trivial subgroup
- that Cayley graphs are always vertex-transitive and connected when the
  generators generate the group, while Schreier graphs need be neither
- what the collapse costs: merged rooms mean merged edges, and some moves become
  invisible — which is why a lower bound derived from the coarse map can be
  strictly below the true distance

## 7. Self-verification before reporting done — MUST

Do not declare the build finished on inspection alone. Run these:

**A. Structural invariants**, over all `n ∈ [3,6]`, `k ∈ [1,n−1]`, `c ∈ {3,4}`:

1. `|V_Cayley| = n!`
2. `|V_Schreier| = C(n,k)`
3. every fiber has exactly `k!(n−k)!` members
4. every Cayley edge projects to a Schreier edge **or** to a loop — this is the
   morphism check and it fails loudly if §2.5 was ignored
5. the Cayley graph is regular of degree `2(n−c+1)`

**B. Known cases**

- `c=4, n=4, k=2`: the Schreier graph has 6 vertices and **2 components**
  (`{0011,0110,1100,1001}` and `{0101,1010}`), with degrees ranging 1–2.
- `c=3`: the Schreier graph is connected for every tested (k,n), while the
  Cayley graph has exactly 2 components (the generators are even).

**C. Rendering** — load the page headless (Playwright/Puppeteer), wait for the
layout to settle, click START, screenshot mid-collapse and after, open HELP,
and confirm **zero console errors and zero page errors**. Look at the
screenshots: light beads must be visible, the collapsed left panel must
coincide with the right panel, and no text may overflow its card.

**D. Sweep** — change (n,k,c) across at least five combinations including
n=6 (720 Cayley vertices) and confirm no errors and no frame-rate collapse.

Report which checks ran and what they returned. "Looks right" is not a result.

## 8. Pitfalls observed while building the original

- Using `σ∘g` instead of `g∘σ` — panels stop corresponding; see §2.5.
- Canvas-roundtrip color interpolation — see the note in §4.3.
- Pure-white beads on a near-white canvas — invisible; darken to ~`#e9edf5`.
- Forgetting that consecutive 3-cycles generate only `A_n`, then shipping a UI
  that says "components: 2" with no explanation.
- Writing the live paragraph as unconditional prose, so it asserts things that
  are false for some parameter settings.
- Not clamping `k` when `n` decreases — leaves `k ≥ n`, and the vertex set is empty.
- `devicePixelRatio`: size the canvas backing store by DPR and scale the context,
  or everything is blurry on a retina display.
